# Phase 4: AI弱点分析＆パーソナライズ問題生成 実装計画

## 1. 目的・概要
ユーザーの学習成績（カテゴリ別正答率や過去の不正解データ）を元に、Gemini APIを活用して弱点を分析し、その弱点を補強するための**新しいオリジナル模擬問題を動的に生成・出題**する機能を実装する。
PWAとしての完全オフライン・ローカルファーストの利点を損なわないよう、バックエンド（サーバー）は構築せず、ブラウザから直接APIをコールするアーキテクチャとする。

## 2. 開発ステップ

### Step 1: ダッシュボードUIと設定画面の構築
- **APIキー設定**: `index.html` に、ユーザーが自身の「Gemini APIキー」を入力して `localStorage` に保存できる設定モーダルを追加する。
- **分析ダッシュボード**: `Chart.js` を導入し、現在の成績（分野別の正答率）をレーダーチャートなどで視覚化するダッシュボード画面を構築する。

### Step 2: AI分析＆アドバイス機能（コアロジック）
- **`src/js/ai.js` の新設**: Gemini API（REST API呼び出し、またはSDK）と通信するモジュールを作成する。
- **プロンプトエンジニアリング**: `storage.js` から学習データ（`categoryStats`）を取得し、「あなたはプロのAWS講師です。以下の成績データを見て、最も正答率が低い分野についてアドバイスしてください」というプロンプトを構築・送信し、結果をダッシュボードに表示する。

### Step 3: AIによる動的問題生成機能
- **JSON生成プロンプト**: ダッシュボードに「AIに弱点克服問題を5問作らせる」ボタンを配置。Geminiに対して厳密なJSONスキーマを指定したプロンプトを送信する。
- **データストック**: 受信したJSON文字列をパース（解析）し、バリデーションを行った上で `localStorage` 内の新しい保存領域 `customQuestions` に保存する。

### Step 4: クイズ画面（ミニテスト）との統合
- **クイズロジックの拡張**: `quiz.js` を修正し、通常の固定データ (`data/*.json`) だけでなく、生成済みの `customQuestions` を読み込んで「AI生成問題テスト」として出題できるモード（例: `?course=saa-c03&mode=ai-custom`）を追加する。

## 3. 追加するデータ構造 (`localStorage`)

```json
// 1. Gemini API Key
"geminiApiKey": "AIzaSy..."

// 2. カスタム問題ストック

  {
    "id": "ai-gen-1714920000",
    "courseId": "saa-c03",
    "category": "secure-arch",
    "difficulty": 3,
    "question": "VPCエンドポイントとNATゲートウェイの違いについて...",
    "options": ["...", "...", "...", "..."],
    "answerIndex": 2,
    "explanation": "理由は..."
  }
]
```

## 4. 懸念事項と対策
- **JSONフォーマットの崩れ**: AIが生成するテキストにマークダウン（```json）が含まれてパースに失敗するケースがあるため、正規表現を用いた厳密なクリーニング処理を実装する。
- **APIコストとレイテンシ**: 一度に生成する問題数を3〜5問に制限し、待ち時間にはローディングアニメーション（プレースホルダー）を表示してUXを保つ。
